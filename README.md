# Tdrive Sync — إضافة Obsidian للمزامنة مع Tdrive

مزامنة ثنائية الاتجاه بين الـ Vault (ملاحظات `.md` والصور وPDF والصوت وغيرها) واستضافتك Tdrive عبر واجهتها REST مباشرةً، دون خادم وسيط.

> **آخر فحص API حي مسجل:** 2026-11-10. حذف المجلد بعد revision مكتمل نجح، وأصبح القفل الذري وifEmpty وشروط contentVersion وتعداد الجلسات متاحة. الإصدار 1.8.0 دمج هذه القدرات؛ الأدلة القديمة محفوظة مع حالة الإصلاح في `docs/API-ISSUES.md`. هذه نتائج تاريخية وليست تأكيدًا لحالة الخادم اليوم.

> **التحقق:** نسخة نشر **1.8.3**: نجح `npm test` في **775 حالة**، منها **108 حالات جديدة لحل التعارضات** و**96 حالة إضافية محفوظة من المستودع**. النتائج والحدود في `docs/TEST-REPORT.md`؛ التدقيق السابق وإصلاحاته في `docs/QA-AUDIT-2026-11-13.md`. نجاح الاختبارات ليس شهادة خلو من جميع العيوب، ولم تُختبر واجهة التطبيق الحقيقي أو كتابة API حية في هذه المرحلة.

## التثبيت اليدوي
1. فك ضغط `tdrive-sync.zip` ستحصل على مجلد `tdrive-sync` فيه `main.js` و`manifest.json` و`styles.css`.
2. انسخ المجلد إلى `<مجلد الـ Vault>/.obsidian/plugins/tdrive-sync/`.
   - **ويندوز:** افتح مجلد الـ Vault، فعّل "إظهار العناصر المخفية"، وانسخ إلى `.obsidian\plugins\`.
   - **أندرويد:** بمدير ملفات يعرض المجلدات المخفية (مثل Files by Google أو Solid Explorer) انسخ المجلد إلى `<Vault>/.obsidian/plugins/`.
3. في Obsidian: الإعدادات ← Community plugins ← أوقف Restricted mode ← فعّل **Tdrive Sync** (أعد تحميل القائمة أو أعد تشغيل التطبيق إن لم يظهر).

### التحديث عبر BRAT
ثبّت BRAT من Community plugins، ثم استخدم **Add Beta plugin** مع المستودع `https://github.com/Killer2B/tdrive-sync-`. تنشر الإصدارات بوسم يطابق `manifest.json`، وتبقى إعداداتك وسجل المزامنة خارج ملفات التحديث. حزم التثبيت متاحة في [GitHub Releases](https://github.com/Killer2B/tdrive-sync-/releases/latest).

## الإعداد
1. في Tdrive: Account ← API keys، أنشئ **مفتاحًا مخصصًا لهذه الإضافة** (قابلًا للإلغاء).
2. الإعدادات ← Tdrive Sync: الصق المفتاح، تحقق من عنوان الخادم `https://tdriver.x2o.workers.dev`، وحدّد المجلد البعيد (الافتراضي `/Obsidian/<اسم الـ Vault>/`).
3. اضغط **اختبار** ثم **فحص شكل استجابات API** (يكتب أسماء الحقول فقط في السجل لتأكيد التوافق).
4. جرّب أولًا نمط **رفع فقط** على Vault تجريبي، ثم **ثنائية الاتجاه**.

## الأوامر (Command Palette)
Tdrive Sync: Test Connection · Sync Now · Approve Pending Deletions · Upload Current File · Download Remote Changes · View Conflicts · View Sync Log · Pause Sync · Resume Sync. إضافةً لأيقونة الشريط الجانبي وعنصر شريط الحالة (سطح المكتب).

## الإعدادات
| الإعداد | الوصف |
|---|---|
| عنوان الخادم | HTTPS إجباري (ما عدا localhost للتطوير). المفتاح لا يُرسل لأي نطاق آخر. |
| API Key | يُحفظ نصًّا عاديًا في `data.json` داخل مجلد الإضافة. |
| المجلد البعيد | جذر المزامنة على Tdrive. |
| نمط المزامنة | ثنائية الاتجاه / رفع فقط / تنزيل فقط. |
| سياسة الحذف | نقل إلى السلة (سلة Tdrive أو سلة Obsidian — قابلة للاسترجاع) أو إيقاف الحذف كليًا. لا حذف نهائي أبدًا. |
| حد الحذف | إن تجاوز عدد الحذف المطلوب هذا الحد تُحجب كل عمليات الحذف في تلك الجولة. |
| مزامنة تلقائية | بالدقائق؛ تعمل أثناء فتح التطبيق فقط. |
| الاستثناءات | أنماط glob (`Private/**`, `**/*.tmp`). كل ما يبدأ بنقطة (`.obsidian`, `.git`, `.trash`) مستثنى دائمًا، وكذلك سجل المزامنة. |

## التعارضات
إذا تغيّر الملف محليًا وبعيدًا منذ آخر مزامنة، يُوقف الاستبدال التلقائي ويُجمَّد المسار. تُحفظ النسخة البعيدة محليًا باسم `الاسم (Tdrive conflict التاريخ).md` مع تخصيص اسم آخر عند التصادم. افتح **View Conflicts** واختر: الاحتفاظ بالمحلية / البعيدة / النسختين / إلغاء. لا تُحذف نسخة التعارض تلقائيًا. الكتابة المحلية مدعومة بالتحقق ونسخ الاستعادة؛ لا تمثل ضمان CAS عام أمام كل كاتب خارجي.

من **1.8.3** يفتح الأمر التعارض النشط أو الوحيد مباشرة. يبقى الحوار مفتوحًا أثناء التحقق والرفع، مع منع الضغط المكرر وعرض الخطأ أو مسودة الدمج بدل الإغلاق الصامت. إذا تغيّرت نسخة راجعتها، استخدم **تحديث المعاينة** قبل اختيارها مجددًا.
- **المحلية:** يعتمد المحتوى المحلي الملتقط عند الاختيار، ويتحقق منه قبل إنهاء التعارض. أي تحرير لاحق لا يدخل الرفع خفيةً؛ تبقى نسخ الاستعادة.
- **البعيدة:** يحفظ احتياطًا محليًا عند اختلاف المحتوى، ثم يطبق البايتات التي تحقّق منها ضمن طابور الكتابة المدعوم.
- **حفظ النسختين:** ينشر نسخة المحتوى البعيد السابقة باسم مستقل `Tdrive kept remote` على الجهاز وTdrive أولًا، ثم يعتمد المحلية للملف الأصلي. استكمال المحاولة يعيد استخدام النسخة المثبتة عند فقد رد أو فشل حفظ، ولا يتطلب حذفًا من الاستضافة.
- **الدمج:** للنص UTF-8 الصحيح مع نسخة أساس، بحد 64 KiB لكل مدخل. عند تداخل التعديلات تظهر مسودة يمكن فتحها داخل Obsidian؛ لا تُنشر العلامات أو يعلن الحل ناجحًا. حرر الملف الأصلي ثم اختر المحلية أو النسختين.

تُنهى التعارضات المتطابقة تلقائيًا فقط بعد قراءة البايتات الحالية والتحقق من الهوية والإصدار، وبحد 8 MiB وفلاتر المزامنة. لا اختيار تلقائي بين محتويين مختلفين، ولا إنهاء خفي لنقل معلق أو محاولة حفظ نسختين غير مكتملة. تبقى النسخ التاريخية، وتستمر مزامنة بقية الملفات حتى أثناء انتظار قرارك.

## الأمان
- استخدم مفتاحًا مخصصًا وألغِه من Tdrive إذا فُقد الجهاز أو شاركت مجلد `.obsidian`.
- لا تُطبع المفاتيح في السجلات (تُحجب `tdk_…`)، ولا `eval`، ولا تحميل كود من الخادم.
- لا يُعتمد نجاح الرفع دون إثبات محتواه، ولا تُقبل موافقة حذف لنسخة تغيرت بعد المراجعة. قد يلتزم الخادم بالرفع قبل فقد الرد؛ يحتفظ العميل بسجل العملية لاستعادة إقرارها بدل تكرار الكتابة أو إلغاء بيانات ملتزمة.

## القيود
- ملف `tdrive-sync.zip` الجديد يحتوي مجلد `tdrive-sync` فقط؛ فكّه داخل `.obsidian/plugins/` لا داخل مجلد الإضافة نفسه. لا يحتوي مفتاح API أو تاريخ المزامنة، ولا يغيّر إعداداتك الموجودة. لا تشارك ZIP القديم إذا كان يحتوي `data.json` أو `sync-state.json`.
- يتبع التنفيذ عقد API الموثق حاليًا. اختبرت دورة الكتابة بملفات مولدة في مجلدات معزولة؛ قراءة ملفات المستخدم والتحقق من محتواها لا يغيرها. فحص `npm run check:api` يظل قراءة فقط دون طباعة المفتاح أو أسماء الملفات.
- النقل المكتشف يحافظ على معرّف الملف. حدث إعادة تسمية مجلد في Obsidian يشمل ملفاته، حتى المعدلة؛ النقل أثناء إغلاق التطبيق قد يحتاج مقارنة أو موافقة حذف إذا لم يوجد دليل واضح.
- تُحمَّل الملفات الكبيرة كاملة في الذاكرة أثناء الرفع/التنزيل؛ تجنّب مئات الميغابايت على أجهزة ضعيفة.
- استبدال ملف محلي قائم يتطلب أن تكون النسختان UTF-8 قابلتين للتحويل دون تغيير البايتات وأن تتوفر `vault.process`. إذا تعذّر ذلك يُرفض الاستبدال بـ`LOCAL_UNSAFE_REPLACEMENT` مع إبقاء الأصل؛ تنزيل ملف ثنائي جديد ورفع التعديلات المحلية يظلان مدعومين. لا تضمن أحداث التغيير وحدها حفظ تحرير ثنائي وقع داخل طابور Obsidian.
- لا مزامنة في الخلفية عندما يعلّق Obsidian (أندرويد).
- اكتشاف التعديل البعيد يعتمد على هوية الملف وجيل المحتوى والبصمة عند توفرهما؛ في مسارات legacy يلزم تحقق محتوى إضافي ولا يُعامل الحجم المتساوي وحده كإثبات تطابق.

## سجل التغييرات
- **1.8.3:** حوار حل يبقى مفتوحًا مع نتيجة واضحة ومسودة دمج قابلة للفتح؛ حفظ النسختين ينشر نسخة مستقلة على Tdrive قبل تحديث الأصل؛ snapshots وhash guards للكتابة والرفع؛ استكمال فقد الرد أو فشل الحفظ دون تكرار IDs/PATCH؛ إنهاء تلقائي للتطابق المثبت فقط مع الاحتفاظ بالنسخ وعدم الحسم الصامت للمختلفة. نجحت **679/679** حالة، منها **108** جديدة؛ التفاصيل والحدود في تقرير الاختبار.
- **1.8.2:** إصلاح عيوب QA في سلطة السجل الموروث وموافقات الحذف والنقل الملتبس وإثبات الرفع واستعادة الالتزام؛ تثبيت إصدار manifest عبر full/ranged/delta وإبطال snapshot القديم بعد رفض الإصدار؛ أسماء نسخ تعارض إنشاء فقط، تنظيف staging غير قاتل، gzip بلا deadlock، وقارئ ZIP يتحقق من CRC والحدود وطول DEFLATE. استبدال محلي قائم بلا مقارنة آمنة يُرفض مع إبقاء الأصل. يشمل `npm test` الآن حالات QA؛ النتيجة النهائية **571/571** دون فشل أو تخطي أو إلغاء.
- **1.8.1**: عرض النسخة المحملة فعليًا ومعلومات الجلسات التي تحجب حذف المجلد، بما فيها تواريخ الانتهاء، دون إلغاء أي بيانات. الجلستان القديمتان داخل «تمرين» أبقيتا بقرار المستخدم؛ إصلاح committed السابق لا يعالج pending التي ما زال API يعدّها نشطة. نجح البناء و450 اختبارًا؛ إعادة تحميل الإضافة داخل Obsidian ضرورية لتشغيل النسخة الجديدة.
- **1.8.0**: التكامل مع API المصحح: leases ذرية مجددة ومحفوظة في الذاكرة فقط؛ حذف ifEmpty؛ شروط expectedVersion؛ تمييز contentVersion عن ترتيب النسخة المؤرشفة؛ نقل metadata ذري؛ التعامل مع جلسات الحساب ومع تعارضات الإصدار والقفل دون إلغاء البيانات المرحلية تلقائيًا.
- **1.7.11**: تصحيح نوع جسم الطلب عند إرسال الأجزاء عبر Obsidian إلى ArrayBuffer بنطاقه الصحيح؛ حماية الاستبدال من تعديل بعيد يحدث بعد التخطيط؛ إثبات محتوى PATCH بدل الاكتفاء باستجابة metadata؛ الحفاظ على تسمية بعيدة تغيرت أثناء التحديث. نجح البناء والحزمة و324 اختبارًا، مع اختبار CDC حي ببيانات UTF-8 مولدة. خلل API الخاص بحذف مجلد يحوي revision مكتمل ما زال موثقًا ولا يتحايل عليه العميل.
- **1.7.10**: معالجة أخطاء المزامنة المعاد إنتاجها عبر تشغيل متتابع وفشل تنزيل وتعديلات متزامنة؛ كتابة عبر واجهة Obsidian مع نسخة استعادة وفحص الفهرس؛ حفظ سجل متسلسل؛ جدولة لاحقة للتعديلات؛ ربط حل التعارض بالمحتوى المعروض؛ استئناف revisions بسجل جلسات مملوك للجهاز؛ إظهار عائق الخادم بدل تكرار الخطأ؛ حزمة ZIP خالية من المفاتيح وسجل المستخدم. هوية الجهاز مستقلة عن نسخ سجل المزامنة.
- **1.7.9**: استعادة المصدر الموافق للنسخة المثبتة 1.7.8 بدل البناء من مصدر 1.0.6 القديم؛ تصحيح عقد المجلدات، حجم أجزاء الرفع، حماية التشفير والاستبدال، التحقق من التنزيل وdelta، حدود وموافقات الحذف، سياق الحساب/الجذر، الكتابة المحلية والإيقاف والتعارضات. تغيير السياق أو أول تشغيل لسجل قديم غير مربوط بحساب يعيد مقارنة المحتوى بأمان؛ لا يحذف ملفاتك، ويحفظ السجل السابق داخل `meta.previousScopeLedger`.
- **1.0.5** — إصلاحات المجلدات والحذف والتتبع:
  - **الحذف المحجوب لم يعد صامتًا:** عند تجاوز حد الحذف (مثلًا حذف أو إعادة تسمية مجلد فيه أكثر من 10 ملفات) تُحفظ القائمة وتظهر في لوحة الحالة مع إشعار، وأمر جديد **Approve Pending Deletions** يعرض الملفات ويطبّق الحذف (إلى السلة) بعد موافقتك. الموافقة لا تتجاوز حماية "الـ Vault/المجلد البعيد فارغ". سابقًا كان الحذف يتجمّد للأبد وتبقى نسخ مكررة بعد إعادة تسمية مجلد.
  - **كل التحذيرات تُكتب في سجل المزامنة** (كانت تُهمل ولا تظهر في أي مكان).
  - **المجلدات الفارغة تُزامَن:** مجلد جديد فارغ محليًا يُنشأ على Tdrive، والعكس، ثم يُتتبَّع فيُنقل حذفه لاحقًا.
  - **لا يُنقل مجلد محلي للسلة إن بقي فيه محتوى مخفي** لا يراه فهرس Obsidian.
  - **حفظ السجل أثناء التشغيل** كل 20 عملية، فلا تضيع نتائج المزامنة إن أُغلق Obsidian فجأة (أندرويد).
- **1.0.4** — حذف المجلدات يعمل الآن في الاتجاهين (محليًا ← Tdrive، وTdrive ← محليًا) بشرط أن يكون المجلد فارغًا، وبنفس ضمانات حذف الملفات. أمر جديد **Clean Empty Remote Folders** لتنظيف المجلدات الفارغة التي تركتها النسخ السابقة.

## التحديث والإزالة
- **تحديث:** استبدل `main.js` و`manifest.json` و`styles.css` بالجديدة وأعد تحميل الإضافة. ملف `sync-state.json` (السجل) و`data.json` (الإعدادات) يبقيان.
- **إزالة:** عطّل الإضافة ثم احذف مجلد `tdrive-sync`. ملفاتك على Tdrive وفي الـ Vault لا تتأثر. لإلغاء الوصول ألغِ المفتاح من Tdrive.
