## المجلدات

- المسارات تبدأ وتنتهي بـ `/`، والجذر `/`، والأسماء مقطع واحد مع تطبيع NFC.
- `GET /api/v1/folders?path=/parent/` يعيد `data.folders` كمصفوفة أسماء نصية، لا معرّفات.
- `GET /api/v1/files?path=/parent/` يعيد `data.files` و`data.folders` و`data.nextOffset`.
- الإنشاء: `POST /api/v1/folders` بجسم `{ "path": "/parent/", "name": "child" }`.
- الحذف: `DELETE /api/v1/folders?path=/parent/&name=child`. لا تجربة `/folders/:id` أو حذف المجلد الأب أو `/files/:id` بدلًا منه.
- `409 ALREADY_EXISTS` يشمل الأسماء المحجوزة في السلة. الإضافة تعيد قراءة الأب ولا تعتبر المجلد موجودًا إلا إذا ظهر فعلًا؛ وإلا تعرض الخطأ دون نجاح وهمي.
- حذف مجلد يحذف جميع محتوياته إلى السلة حسب التوثيق. الإضافة تعيد التأكد من فراغه قبل الطلب، وتبقي المجلدات المحلية ذات المحتويات المخفية.

## الملفات والأجزاء

- جميع JSON داخل `{ "ok": true, "data": ... }`؛ الأخطاء `{ "ok": false, "error": { "code", "message" } }`.
- `GET /api/v1` هو مرجع الحدود. الحد الحي `chunkBytes = oneShotMaxBytes = 5242880` بايت، وليس `5000000`.
- الأجزاء الثابتة تتبع حجم جزء الخادم بالضبط، أما CDC فيرسل وصف `chunker` وعدد الأجزاء وإزاحاتها وأحجامها.
- بصمة الملف المجزأ `SHA256(hashes.join("\n"))`، وليست SHA256 لكل بايتات الملف مجتمعة. التحقق من المحتوى يستخدم `chunks[].checksum` لكل جزء.
- التحديث يحافظ على المعرّف عبر `PATCH /files/:id {content:{inline}}` أو جلسة `{baseId, mode:"replace"}`. فشل التحديث لا يبرر حذف الأصل ثم إعادة إنشائه.
- التشفير والضغط يطبّقان أيضًا على الاستبدالات الصغيرة، وليس فقط الرفع الأول.
- `429/503` مع `Retry-After` يفرض حد الانتظار الأدنى. فشل استجابة أو تجزئة غير صحيحة يوقف العملية ولا يعد نجاحًا.
- إعادة تركيب delta تنقل كل جزء إلى إزاحته الجديدة وتتحقق من بصمته؛ لا يكفي تعديل إزاحات الأجزاء الجديدة فقط. delta الخاص ببايتات مشفرة/مضغوطة لا يطبق على النص المحلي المفكوك.

## قيود تحتاج دعم الخادم

- لا يوجد في العقد الموثق حذف مجلد مشروط بفراغه (`ifEmpty` أو مقارنة إصدار). يوجد سباق محتمل بين فحص الفراغ وإضافة جهاز آخر ملفًا ثم تنفيذ الحذف. يحتاج المنع الكامل إلى شرط ذري داخل API؛ هذه فجوة في العقد، وليست خطأ خادم تمت إعادة إنتاجه.
- ملف القفل المخفي حماية استرشادية، وليس قفلًا موزعًا ذريًا بين الأجهزة. الضمان الكامل يحتاج lock/lease ذريًا من الخادم.
- أي خطأ خارجي جديد يجب إرفاق HTTP status و`error.code` و`X-Request-Id` به. لا تمسح السلة أو المفتاح للتشخيص.
